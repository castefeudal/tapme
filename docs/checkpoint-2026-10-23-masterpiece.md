## Где остановились: touch WebKit

Файл tests/touch.spec.ts оставлен с временной диагностикой console.log и screenshot. BODY, создание плана и открытие диалога работают через tap. При close.tap WebKit сообщает, что div.dialog-top перехватывает события.

Измеренная геометрия кнопки: x=304.6, y=88.4375, 44×44; document.elementFromPoint в её центре корректно возвращает SVG path внутри кнопки. CSS viewport 390×844, devicePixelRatio=1.25 даже при deviceScaleFactor=1. Предположение, пока НЕ доказанное: проблема координат touch-протокола Windows WebKit при системном масштабе 125%, а не перекрытие в продукте.

Следующий диагностический шаг: записать фактические clientX/clientY и target события pointerdown в capture-фазе при tap и сравнить с запрошенным центром. При подтверждении масштаба исправить калибровку тестовой инфраструктуры; не использовать force:true или случайные CSS/z-index обходы. После решения убрать временную диагностику. Снимок docs/evidence/touch-contact-debug.png игнорируется Git.

Последняя оптимизация observer планировщика: intersectionRatio >= 0.1, threshold: 0.1 в src/main.tsx. Существенного улучшения Lighthouse не показала; при необходимости пересмотреть по реальному поведению, не гнаться за баллом.
